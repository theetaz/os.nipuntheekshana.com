# Kottu OS keyboard walkthrough

Use a fresh desktop session at 1440 × 900. Repeat in light and dark, with reduced motion enabled. Use Tab and Shift+Tab throughout; do not use the mouse to recover focus.

1. Tab to the skip links. Activate Simple view, follow a section link, and use Back to the desktop. Confirm one visible main heading and a visible focus ring throughout.
2. Press Alt+2 to focus the desktop props. Use the arrow keys to visit the props, Enter to open one, and Escape to dismiss an overlay. Check the prop name is announced. Move a prop with Shift+arrows, cancel with Escape, and verify its previous position returns.
3. Tab to Workspaces. Use Left/Right, digits 1–5, Home and End. Check the selected dot, section scroll position and focus remain consistent. Control+1–5 on macOS, or Super+1–5 elsewhere, must work outside editable fields.
4. Focus a project card. Confirm its complete title, keyboard preview and focus ring. Enter opens the project. Return and move to another card; the previous preview must close. Under reduced motion, the command appears immediately.
5. Go to Board. Activate + leave a message, enter a name and message, and submit. Tab must stay inside the compose window or phone sheet. Check validation errors are announced, successful submission closes the composer, and the new note appears. Escape leaves the desktop compose window open. Alt+W closes it through its draft guard and restores focus to the opener.
6. Open Projects and Writing. Tab wraps within the focused window. Use Alt+backtick to switch windows, Alt+[ and Alt+] to snap, Alt+Z to maximise or restore, and the Window menu to enter keyboard move mode. Arrow keys move, Enter commits and Escape cancels. Minimise, restore and close each window; focus must return to a visible control.
7. Repeat Board and app navigation at 390 × 844. The sheet header, App commands menu and Home action must be reachable. Open and dismiss menus with the keyboard, and verify the background cannot receive focus while a modal sheet or composer owns it.

Record browser, theme, motion preference, observed result and any remaining issue in the release verification report. Axe results supplement this walkthrough; they do not replace the focus checks.
